# Custom Modules Coupling Map (Odoo 19)

> **Checked against odoo19 on 2026-10-31.** Built 2026-10-13 on the odoo20 tree (9 Haiku scouts, one per module group; an Opus verifier on 22 edges) and reduced for Odoo 19. The custom modules in odoo19 are the 20.0 code of 2026-10-23 migrated to 19.0 (`gec_odoo_modules` commit e8588d7), so most couplings hold. Kept: the rows whose modules, fields, methods, xmlids and files all exist in odoo19. Dropped: rows on modules odoo19 does not have (gec_vat_declaration, gec_property_tax_report, hotel_rms, signify, bpmn_process_management, the om_* modules), the 2026-10-28 Tax Category Code VAT class, the gec_localization `is_company` override, the v20 Form 30 plan B and vendor-bill design notes, and data facts from the v20 database. Line numbers were removed: about a third no longer land on the cited line in odoo19, so grep the name in the named file. The check was by name; counts and behaviour in the kept rows were not re-verified one by one. Keep it current: a flow sweep that finds a coupling missing here adds it.

This map is not a full list of what a change touches. It comes from one extraction pass per module. When it says "no reader found", nothing was found in the files that pass searched (mostly `*.py`, `*.xml`, `*.csv`, `*.js`). That does not mean the change is safe. Past misses, such as the withholding rate rules and the salary journal entries, came from data-only links: tax xmlids, account xmlids, salary rule codes and contact flags. Searching for model names does not find these. Sections 1 and 3 put them first.

**Legend**
- Untagged facts were read in code during the extraction: [Certain]. Other tags: [Likely] (strong inference), [Unclear] (not settled), [from doc] (only a `documentations/` rule says so).
- Paths: `module/...` is relative to `custom_addons/gec_odoo_modules/`. `custom_addons/...` covers other roots. `addons/`, `enterprise/`, `odoo/` and `documentations/` are relative to the odoo19 root.
- A file named in a cell belongs to the module named just before it in that cell.
- Row IDs (T, A, P, B, S, R, J, E, D, N, O) are referenced from sections 2 and 3. Gaps in the numbering are dropped rows.

## 3. Known blind spots

**Hidden module links (no `depends`, found only by method or field name)**
- rs_einvoice, rs_waybill and employee_registry_rs call rs_base_methods through getattr/hasattr and do not depend on it. rs_base_methods depends on all three. Renaming any `res.users` rs_* method breaks them silently: the cron returns empty with a log line (E1; rs_einvoice/models/rs_einvoice_cron.py; rs_waybill/models/rs_waybill_sync.py).
- rs_base_methods redefines 11 rs_einvoice methods and 5 rs_waybill actions by name; all call super except `action_save_invoice`, which blocks the old path on purpose (verified 2026-10-13) (E3, E4). A new override in rs_einvoice or rs_waybill must keep the same names working.
- bog_bank redeclares the gec_bank `gec_bank_state` selection. A new state in gec_bank must also be added there [Likely] (bog_bank/models/account_payment.py).
- tbc_bank and bog_bank do not depend on gec_localization but read `gec_treasury_code`. It reaches them only through gec_bank's depends (gec_bank/__manifest__.py).

**Data-only links (accounts, codes and xmlids referenced from code or data)**
- Salary PIT has two accounts. Payroll PIT credits `gec_account_331320` (A1). The WHT taxes for resident salary and NR employment book on `ge_account_331310` (A4). A salary withheld through a bill payment and one withheld through a payslip land on different accounts.
- geo_payroll looks up 9 account xmlids. gec_income_tax_report looks up `gec_account_140311`. gec_bank looks up `account_journal_payment_credit_account_id`. A change to an account row in gec_localization's CSV changes payslip entries and Form 30 cells (A1-A8).
- Form 30 matches salary rules by code string and WHT taxes by xmlid (R1, T1). Renaming a rule code or a tax xmlid gives no error. The rows just disappear or lose their income type.
- Jobs that run on every upgrade:
  - gec_localization: tax and account maintenance (gec_localization/data/ge_tax_maintenance.xml).
  - geo_payroll: payroll accounts and default structure (geo_payroll/data/payroll_structure_data.xml).
  - gec_income_tax_report: country codes and the tax income-type map (gec_income_tax_report/data/rs_form30_data.xml).
  - gec_analytic_margin: post-init SQL on `account_account` (gec_analytic_margin/__init__.py).
- Manager edits are protected with noupdate on gec_income_tax_report rate rules. A later data fix in that file will not apply to edited rows (gec_income_tax_report/models/rs_form30_classifier.py).

**Flags on contacts**
- `gec_treasury_code` has 1 writer (geo_payroll data) and 5 readers. bog_bank refuses treasury recipients, so a PIT authority leg routed through a BOG channel is refused [Certain: Pay Salaries calls channel._gec_bank_check, gec_payroll_bank/models/hr_payslip.py; bog_bank/models/account_payment_method_line.py] (P1; gec_payroll_bank/models/hr_payslip.py).
- These values are not plain fields:
  - `pension_fund_member` syncs between contact and employee (P5).
  - `rs_un_id` is a cache cleared by a Tax ID change (P4).
  - `allow_out_payment` blocks sends and payslip payments (P7).
- The rs_waybill `rs_is_foreigner` help text names CHEK_DRIVER_TIN, but the XML reads `waybill.driver_is_foreigner` (rs_waybill/models/res_partner.py; rs_waybill/models/rs_waybill_soap_service.py).
